CUSTOMER WORKFLOW

How to use Vulnerability View

A practical daily workflow for choosing, tracking, and validating vulnerability remediation.

Contextual explanations

Question-mark buttons beside metrics, table headings, progress values, workflow badges, and SLA charts open an explanation. They work with a mouse, touch, or keyboard. Each explanation describes the unit, reporting scope, and whether a value represents open risk, confirmed progress, or manual coordination.

Still open
Unresolved exposure remains, without confirmed clearance in the displayed reporting period. Work can still be marked In progress.
Improved
Some exposure was confirmed cleared during the period, but risk remains. Improved items are already included in open totals.
Fully resolved / fully cleared
Confirmed clearance occurred during the period and no unresolved exposure remains for that entity in the selected scope.
Overdue / deadline unknown
At least one unresolved vulnerability is past its recorded deadline, or deadline evidence is missing. Neither status is counted as a successful completion.
Dashboard work status
Manual coordination only. In progress and Fixed, awaiting collection do not patch machines, update Defender, pause SLA clocks, or prove remediation.

Views and related details

Summary presents current status, severity and progress. Vulnerabilities lists distinct CVEs. Recommendations prioritizes unresolved actions by criticality, known exploit, overdue CVEs, affected machines, and distinct CVEs; there is no separate Prioritization page. Work status is coordination, not proof of a fix. Machines provides inventory, fixed/open CVEs and dated history.

SLA includes open and fully-cleared breakdowns, severity and clearance charts, compliance snapshots and calendar comparisons. Not yet due + overdue + deadline unknown = total open. Within SLA + late + deadline unknown = total cleared in the stated period. CVEs and machines are separate totals. Count links retain matching records and CSV. A CVE clears only when no in-scope machine remains vulnerable; a machine clears only when no in-scope CVE remains open. Unknown deadlines are excluded from the on-time rate. No full clearances means N/A, never 100%.

Reporting contains period comparisons, observed activity, Print / Save PDF and CSV. Executive View retains period and owner controls, severity, clearance and compliance charts, entity details, and exports. Initial inventory is not newly introduced risk. Detection charts distinguish still-detected CVEs from CVEs no longer detected but awaiting an older confirmation rule. Pending software evidence on a still-detected CVE is not full-CVE clearance. Changed software evidence IDs do not prove a fix. Retained-history gaps are unavailable, not zero. A page remains pinned until a newer snapshot is explicitly loaded.

Management totals and progress

Management summaries count unique machines, unique vulnerabilities (CVEs), and recommendations. A CVE on 500 machines is one vulnerability, not 500 vulnerabilities. Software and version evidence does not multiply the headline totals.

Improved means confirmed exposure was removed during the period but risk remains. Fully resolved means confirmed remediation occurred during the period and no unresolved exposure remains for that entity in the selected scope. Pending verification remains open. Overdue risk means at least one unresolved exposure is past its policy deadline; unknown deadlines are not compliant results.

Finding-instance views and counts are not displayed. Underlying collection evidence is retained. Each entity table provides status, drill-down, and an export of all matching entity rows. Activity tables show observed changes, not proof of full resolution.

Daily workflow

  1. Confirm freshness. Check Data refreshed and recent collection runs. Do not make decisions from a failed or unexpectedly old collection.
  2. Understand movement. Review First seen and Remediation observed in the selected UTC window. Use changes since the previous run when you specifically need run-to-run movement.
  3. Choose work. Filter by severity, subscription, asset class, or domain. Use Exposure status → Pending evidence only, or the Pending only shortcut, to isolate retained pending evidence.
  4. Coordinate remediation. Open a recommendation to identify machines and CVEs. Set the dashboard status to In progress when tracking is enabled; perform the actual change through approved management tools.
  5. Fix recognition. The default counts a fix at the first complete collection showing it absent on an active, fresh machine. No extra collection is required. An empty vulnerability list can mean the machine is fully cleared. Pending confirmation belongs to an older or explicitly configured multi-collection rule; Pending verification means collection or machine evidence is insufficient.
  6. Report and escalate. Use Reporting for lifecycle, SLA, and period comparisons. Escalate critical or outside-SLA work that remains blocked.

Common customer scenarios

Daily triage

Recommendations defaults to unresolved actions ranked by criticality and risk. Each action links to its affected machines and CVEs.

Validate yesterday's remediation

Review Fixed in the same window and changes since the previous run. A machine with a fix may still contain other open findings.

Work an overdue backlog

Filter to Critical or High and review open findings outside SLA. Prioritize recommendations that remove the largest current exposure.

Investigate work that did not clear

Find recommendations marked fixed awaiting collection but still detected after the latest successful run, then inspect the remaining machines.

Read the numbers correctly

Vulnerability
A machine is vulnerable to a CVE once, regardless of affected software products or versions. Dashboard totals count distinct CVEs and distinct machines separately. Software records support the assessment and do not multiply either count.
Machine count
Distinct endpoint devices with matching vulnerability evidence. Cloud-only resources may not appear in endpoint inventory.
First seen window
Vulnerability observations first recorded inside the displayed UTC range anchored to the latest collection.
Remediation observed
The first qualified absence used for SLA timing. The default counts evidence fixed immediately; all evidence for the machine/CVE must be gone for full clearance.
Pending confirmation
An older retained or explicitly configured multi-collection rule still requires another qualified absence. The default no longer requires that wait.
Pending verification
Collection or machine evidence is insufficient; no fix is credited. A complete empty vulnerability list on a fresh, active machine does count as clearance.
Previous-run changes
New, reopened, pending, returned, or fixed vulnerability evidence between comparable collections.
Dashboard status
Shared coordination state attached to a recommendation ID. It does not update Defender or perform remediation.
